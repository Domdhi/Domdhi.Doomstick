§01Briefing

Double-click the launcher for your operating system below. A console window opens, you pick a model, the model loads, and the chat UI opens at 127.0.0.1:8765. Only one model runs at a time — to switch, press any key in the launcher window to terminate, then run the launcher again. Everything happens locally; no telemetry leaves the host. /// END TRANSMISSION ///

§01Briefing

You're on a phone — desktop launchers don't apply here. Scroll to the Mobile Field Kit below: each card points at the right consumer app for one capability the kit ships (Wikipedia ZIM, OSM region, GGUF model, OCR, DOOM). Install the apps once, then the USB's data files travel with you. Two pages on the kit work directly in this browser: OCR and DOOM — no app needed. /// END TRANSMISSION ///

§06Field Notes

Hard-earned operational guidance. Read before deploying in anger.

FN·01

Slow first launch?

USB is ~3-4× slower than local disk for model loading (~15 s vs ~4 s for E4B). Once loaded into RAM, generation speed is identical. For long sessions, copy runtime/ and the relevant models/*.gguf to your Desktop and run from there.

FN·02

Stop a running model

Press any key in the launcher window — clean shutdown. Or close the minimized “Gemma 4 …” window in the taskbar / Task Manager / pkill llamafile.

FN·03

Override flags or port

The launcher uses port 8765 and 8 K context. To change, edit start.bat / .sh / .command at the USB root, or run ai-kit\runtime\llamafile.exe with your own flags directly.

FN·04

“This app can’t run on your PC”

Old .llamafile.exe bundle >4 GB — the Windows PE loader rejects it. The current kit ships runtime + weights separately to dodge the limit. Use start.bat.

FN·05

Empty chat / spinning forever

Model is still loading from USB. Wait 30-60 s and refresh. Check ai-kit/llamafile-e4b.log for live progress (look for server is listening).

FN·06

WSL: “APE is running on WIN32”

Prefix invocations with sh: sh ./runtime/llamafile -m models/.... The launcher already does this; the workaround is for ad-hoc commands.

§06mMobile Field Notes

Hard-earned guidance for using this kit from a phone.

FN·M01

USB-OTG might need an adapter

Modern phones use USB-C or Lightning; full-size USB-A sticks need an OTG adapter. Most phones recognize the stick within a few seconds — pull down the notification shade and tap the storage entry to browse, or open your file manager / Files app.

FN·M02

Permissions on first install

Kiwix, Organic Maps, and PocketPal will all ask for storage access on first run. Grant it — that's how they read the kit's files. iOS users go through the Files app picker; Android uses the system file picker or direct path.

FN·M03

Install once, offline forever

Install the apps over a connection (one time), then unplug. The data files travel with the stick — every host you plug into already has the apps. The internet is optional after first install.

FN·M04

Copy to phone for daily use

USB-OTG reads are slower than internal storage. For Wikipedia or maps you'll use daily, copy the relevant file off the stick into your phone's internal storage once. Saves the OTG step on every launch.

FN·M05

iOS file manager quirk

iOS shows USB drives in the Files app under "Browse → Locations". If the drive doesn't appear, unplug and replug — iOS sometimes needs a second handshake. Lightning ports may need an Apple-branded adapter to deliver enough power.

FN·M06

DOOM saves are desktop-only

Browser DOOM works on the phone, but saves persist via redbean's /save endpoint — and redbean only runs on desktop. Mobile DOOM is a fresh playthrough each session. Same engine, same WAD, just no save state.
